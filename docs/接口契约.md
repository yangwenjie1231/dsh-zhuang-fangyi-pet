# 接口契约（冻结版 v1）

> **本文件是三个实现方之间的唯一契约**，任何一方都不得单方面改动。
> 三方：① Host 半边（`index.js` / `src/pet/*.js`）；② 原生 exe（`pet/*.cs`）；
> ③ 窗口内 overlay（`client.js`）。
>
> 改动流程：先改本文件 → 再同步三方 → 最后跑 `tools/test-pet-contract.mjs` 校验。
> 所有事实均来自**本机实测**，不是推测（见 `docs/桌宠开发文档.md` 附录与调研记录）。

---

## 0. 端口与地址自发现

**绝不硬编码 19387**（本机当前值，但可能变）。

| 来源 | 取法 |
|---|---|
| 端口 | `ctx.webServer.port` —— 实测 getter 返回**实际监听端口**（`config.port` 为 0 时也是 OS 分配后的真值） |
| 主机 | `ctx.webServer.host`；若为 `0.0.0.0` 则**映射为 `127.0.0.1`** 再交给 exe |

exe 收到的基址形如 `http://127.0.0.1:<port>`。

## 1. 状态名（`petState`）—— 唯一合法值域

```ts
type PetState =
  | 'waking'     // 插件加载 / exe 首连（瞬时 ~1.5s）
  | 'idle'       // 默认
  | 'listening'  // 收到用户消息 / 新消息入队（瞬时）
  | 'thinking'   // agent/status→running 且无在飞工具；step/start
  | 'working'    // tool/call 在飞
  | 'waiting'    // 在等你审批（approval/asked）
  | 'happy'      // turn/end 且 reason.kind==='completed'（闩锁 happyMs）
  | 'error'      // agent/error / api-session/error / turn/end reason==='error'
  | 'sleeping'   // 全局空闲超时
```

**优先级**（跨会话取最大值，大者胜；数值越大越优先）：

| 值 | 状态 |
|---|---|
| 90 | `working` |
| 80 | `waiting` |
| 70 | `thinking` |
| 60 | `error` |
| 50 | `happy` |
| 40 | `listening` |
| 30 | `waking` |
| 20 | `idle` |
| 10 | `sleeping` |

> 注意与 `桌宠开发文档.md` §4.1 的 `tool > running > error > done > ready > idle` 一致：
> `working`(`tool`) > `thinking`(`running`) > `error` > `happy`(`done`) > `idle`。
> `waiting` 插在 `thinking` 之上：审批阻塞时最该被看到。
> 但 **`error`(60) 低于 `thinking`(70)/`waiting`(80)**：出错闩锁不应盖住随后开始的新回合
> —— 这正是文档 §4.1 要解决的「历史错误不该覆盖当前回合」。
> `thinking`/`working` 一旦出现即清除该会话的 error 闩锁，所以 60 只在该会话**真的停在错误上**时生效。

## 2. 快照 payload（Host → exe / overlay，共用）

```jsonc
{
  "rev": 42,                                  // 单调递增；客户端丢弃 rev 更旧的帧
  "petState": "working",
  "label": "正在调用工具…",                     // 已本地化的短文案
  "since": 1730000000000,                     // 进入当前状态的 epoch ms
  "bubble": {                                 // null = 无气泡
    "id": 137,                                // 单调递增；同 id 不重复弹
    "kind": "both",                           // 'image' | 'text' | 'both'
    "image": "bubble/04.png",                 // 相对 /pet/art/ 的路径；kind 含 image 时必有
    "text": "正在调用工具…",
    "durationMs": 6000,
    "priority": 20
  },
  "sessions": [
    { "sessionId": "session-…", "state": "working", "toolsInFlight": 1 }
  ],
  "nativeAvailable": true,                    // Host 侧 exe 是否在跑（供 overlay 判断是否让位）
  "nativeError": null                         // 不可用原因，字符串
}
```

**SSE 帧格式**（`GET /pet/events`）：

```
retry: 3000\n\n                              ← 首帧，建议重连间隔
event: hello\ndata: {…快照…}\n\n               ← 连上立刻一帧
event: state\ndata: {…快照…}\n\n               ← 之后每次变化
: ping\n\n                                    ← 每 25s 注释心跳（不是事件）
```

**关键**：`data:` 后必须是**单行压缩 JSON**（不能含裸换行）——
C# 侧与 overlay 侧都按「读到空行 = 帧结束」解析。

## 3. HTTP 路由（前缀 `/api/zhuang-fangyi/pet`）

**全部要求** `Authorization: Bearer <token>`（`hello` 之外任何帧缺失 → 401）。

| 路由 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/pet/state` | GET | — | 单个快照 JSON（轮询兜底） |
| `/pet/events` | GET | — | SSE 流（见 §2） |
| `/pet/atlas` | GET | — | `pet.json` 原样（素材清单，见 §4） |
| `/pet/art/<name>` | GET | — | 图片字节；`<name>` 必须在清单白名单内 |
| `/pet/position` | POST | `{"x":100,"y":200,"scale":1.0,"bubbleX":..,"bubbleY":..}` | `{"ok":true}` |
| `/pet/command` | POST | `{"command":"focus-dsh"\|"reload-art"\|"quit"\|"hide"\|"show"}` | `{"ok":true}` |

**信任围栏（三道，缺一不可）**：
1. 本插件前缀长于内核 `/api`，webServer 是「最长前缀胜出」→ 会**先于**内核 admission 执行。
   必须照抄本 profile 已验证的 `dsh-our-free-model/src/trust.js` 做法：
   优先 `ctx.connection.admit(req)`，退回结构复刻（仅 loopback Host、
   拒 `sec-fetch-site: cross-site`、Origin/Referer 必须同 authority）。
2. **一次性令牌**：每次 spawn 由 Host 用 `crypto.randomBytes(24).toString('hex')` 生成，
   经 argv 传给 exe，**不落盘**。围栏只防浏览器/DNS 重绑定，令牌才挡得住本机任意进程。
3. **素材白名单**：由 `pet.json` 派生，**绝不拼接客户端传入的路径**，
   并二次校验 `path.resolve` 仍在 `art/pet` 内（照抄主题插件 `artWhitelist()` 的双保险）。

## 4. 素材清单 `art/pet/pet.json`

**这是 Host 与 exe 之间关于素材的唯一契约。**
`frameHeight` 是产出时的实际帧高；exe **不得假设固定值**，必须按此缩放。

```jsonc
{
  "version": 1,
  "generatedAt": "2026-10-04T14:00:00.000Z",
  "frameHeight": 256,
  "states": {
    "idle":   { "file": "idle.png",   "frames": 33, "frameMs": 36, "anchorY": 1.0 },
    "working":{ "file": "working.png","frames": 33, "frameMs": 36, "anchorY": 1.0 }
  },
  "variants": {
    "idle": ["idle.png", "idle-2.png"]        // 同状态多素材轮换；states 里的必须在其中
  },
  "bubble": [
    { "file": "bubble/01.png", "w": 240, "h": 240 }
  ],
  "missing": [
    { "name": "表情包_08_爱你哦", "reason": "needsCutout" }
  ]
}
```

- `states` 的键**只能是 §1 的状态名**；缺某个状态时 Host 回落到 `idle`。
- `file` 是相对 `art/pet/` 的路径，**必须**同时出现在 Host 的 URL 白名单里。
- `variants` 可选；用于「同状态轮换多样素材」防呆板。
- `bubble` 是气泡表情池（抠好的 PNG + 未占用的 GIF + `wx\3/5.png`）。
- `missing` 列出待人工抠图的素材；**缺失不得导致任何一方报错**。

## 5. exe 启动契约（Host → exe）

Host 用 `ctx.subprocess.spawn` 启动（**不用 `node:child_process` 绕过**）。

```
argv: [<exe路径>,
       --url http://127.0.0.1:<port>     // 基址，见 §0
       --token <48位hex>                 // 一次性令牌，见 §3
       --state <petState>                // 启动瞬间的状态（避免首帧闪错）
       --scale <float>                   // 0.5~2.0
       --opacity <float>                 // 0.3~1.0
       --x <int> --y <int>               // 上次位置；缺省=主屏右下角
       --topmost <0|1>
       --click-through <0|1>
       --bubble <0|1>
       --selftest                        // 无窗口自检；退出码 0=通过
```

`SubprocessSpawnSpec`（**实测契约**）：

```ts
{ argv: readonly string[], cwd: string, stdio: SubprocessStdio, graceMs: number,
  signal?: AbortSignal, env?: NodeJS.ProcessEnv }
// stdio: { stdin:'ignore', stdout:'pipe', stderr:'pipe' }
// handle: { stdin, stdout, stderr, collected, done: Promise<{exitCode, signal}>,
//           terminate(): void, waitForExit(signal?): Promise<boolean> }
```

**exe 侧硬要求**：
- **命名互斥体** `Global\DSH-ZhuangFangyi-Pet`；已被占用 → 立即 `exit(0)`（避免多只桌宠）。
- **连续 5 次 401 → 主动退出**（宿主重启后不留连不上旧令牌的僵尸）。
- 退出码约定：`0` 正常；`1` 自检失败；`2` 互斥体被占；`3` 参数非法；`4` 素材缺失。
- 宿主侧：exe 在 `t < 10s` 内非零退出 → **不自动重启**，置 `nativeError` 并在 `/diag` 暴露。

## 6. 素材转场（不变式）

- **绝不读会话消息正文**（文档 §十 红线）：只消费事件元数据与 `turn/end` 的 `reason.kind`。
- **透明底必须保留 alpha**：PNG RGBA，绝不 `flatten()`，否则透明区残留 RGB 变彩色噪点。
- **按状态懒加载**：12 张 GIF 合计 ~12MB，绝不能全部预加载；一次只解码当前状态那一张条带。
- 精灵图是**横向条带**（`frames × frameHeight` 宽），一份产物同时喂
  WPF（`CroppedBitmap` 取帧，**已实测可用**）与 overlay（CSS `animation: steps(N)`）。
