# 接口契约（冻结版 v1）

> **本文件是三个实现方之间的唯一契约**，任何一方都不得单方面改动。
> 三方：① Host 半边（`index.js` / `src/pet/*.js`）；② 原生 exe（`pet/*.cs`）；
> ③ 窗口内 overlay（`client.js`）。
>
> 改动流程：先改本文件 → 再同步三方 → 最后跑 `tools/test-pet-contract.mjs` 校验。
> 所有事实均来自**本机实测**，不是推测（见 `docs/桌宠开发文档.md` 附录与调研记录）。

---

## 0. 端口与地址自发现

**绝不硬编码 19387**（本机当前值，但可能变）。

| 来源 | 取法 |
|---|---|
| 端口 | `ctx.webServer.port` —— 实测 getter 返回**实际监听端口**（`config.port` 为 0 时也是 OS 分配后的真值） |
| 主机 | `ctx.webServer.host`；若为 `0.0.0.0` 则**映射为 `127.0.0.1`** 再交给 exe |

exe 收到的基址形如 `http://127.0.0.1:<port>`。

## 1. 状态名（`petState`）—— 唯一合法值域

```ts
type PetState =
  | 'waking'     // 插件加载 / exe 首连（瞬时 ~1.5s）
  | 'idle'       // 默认
  | 'listening'  // ⚠️ 保留在值域里，但 Host **不再产出**（见下方说明）
  | 'thinking'   // agent/status→running 且无在飞工具；step/start
  | 'working'    // tool/call 在飞
  | 'waiting'    // 在等你审批（approval/asked）
  | 'happy'      // turn/end 且 reason.kind==='completed'（闩锁 happyMs）
  | 'error'      // agent/error / api-session/error / turn/end reason==='error'
  | 'sleeping'   // 全局空闲超时
```

> ⚠️ **`listening` 保留但不产出**（2026-10-07 用户决定："Listening 这个状态几乎不会出现
> （过的很快，而且意义不大），相关的内容并入其他的吧"）。
>
> 它原本是 `inbox/inserted` 置的一个 **1.2 秒闩锁**、优先级 40，低于 `thinking`(70) ——
> 于是只有在"你刚发完消息、agent 还没起跑"的那 1.2 秒里才可能成为 `petState`；
> 而它那组图（眨眼等）与 `idle` 撞脸，闪过也分辨不出。现在**收到消息只弹气泡**
> （`inbox/inserted` 事件本来就有专属气泡与文案）。
>
> **保留条目是为了向后兼容**：老客户端、老设置照常工作，Host 只是不再产出它。
> 渲染方仍应能接受 `listening`（万一遇到旧 Host 的帧），且**不得**因此报错。

**优先级**（跨会话取最大值，大者胜；数值越大越优先）：

| 值 | 状态 |
|---|---|
| 90 | `working` |
| 80 | `waiting` |
| 70 | `thinking` |
| 60 | `error` |
| 50 | `happy` |
| 40 | `listening`（保留，不产出） |
| 30 | `waking` |
| 20 | `idle` |
| 10 | `sleeping` |

> 注意与 `桌宠开发文档.md` §4.1 的 `tool > running > error > done > ready > idle` 一致：
> `working`(`tool`) > `thinking`(`running`) > `error` > `happy`(`done`) > `idle`。
> `waiting` 插在 `thinking` 之上：审批阻塞时最该被看到。
> 但 **`error`(60) 低于 `thinking`(70)/`waiting`(80)**：出错闩锁不应盖住随后开始的新回合
> —— 这正是文档 §4.1 要解决的「历史错误不该覆盖当前回合」。
> `thinking`/`working` 一旦出现即清除该会话的 error 闩锁，所以 60 只在该会话**真的停在错误上**时生效。

> ⚠️ **`thinking` 与 `working` 是交替，不是阶段**：`tool/call` 进来就变 `working`，
> `tool/result` 出去又回 `thinking`，而一次本地工具常常只有几十~几百毫秒。
> Host 侧因此给**过程态**加了**最短驻留**（`minStateDwellMs`，默认 **2000ms**）：
> 切到新状态不足 2 秒就继续显示上一个。豁免名单 = 事件时刻
> （`happy` / `error` / `waiting` / `waking` / `sleeping`），它们立即生效 ——
> 「完成啦」「出错」「等你审批」晚 2 秒会让语音与画面对不上。
>
> 这条**只影响"对外显示的状态"**，语义状态机（`sessionState()`）本身不变。
> 且闩锁**必须逐会话应用**并写进快照的 `sessions[].state`：exe 的
> `EffectiveState()` 会拿各会话状态与顶层 `petState` 比优先级取最大，
> 只锁顶层会被原始会话状态推翻（抖动照旧）。

> **`growth` / `today` 块的语义（v10）**：
>
> - **缺整块（旧 Host）→ 客户端与 exe 静默忽略**（零回归）。设置页「今天」
>   页签与右键菜单「今天」一行都读它们；缺了**不会报错**，只会让那两处
>   永远显示"没有记录" —— 所以两处都做了 `?? 0` / `?? []` 的兜底。
> - `growth.milestone` **必须总是存在**（没有时是 `null`，不是缺键）：
>   客户端用 `'milestone' in growth` 之外的方式判空会踩到 `undefined`。
> - `today.dayKey` 用**本地日期**（不是 UTC）：东八区早上 8 点之前，
>   UTC 的"今天"还是昨天 —— 用户看到的会是"昨天没记录、今天也没记录"。
> - `recent` 固定给 **7 天**且**按日期升序**，缺的天补 0（趋势图不该有断点）。
>   排序由宿主做，渲染方**不要自己再排一次**（两处各排一次，口径会分叉）。
> - `pomodoro.interrupts` 与 `today.phaseInterrupts` 是**同一个数**的两种视角
>   （前者是当前阶段，后者在阶段结束后归零）—— 阶段结束时宿主读它决定点评。

> **`pomodoro` 块的语义（番茄钟）**：
>
> - **exe 绝不自算"该提醒了"**：阶段结束的判定与提醒都在 Host 里（它是唯一真相）。
>   exe 只用 `endsAt` 做**显示**用的本地插值 —— 每秒推一帧太重，而让两边各判一次
>   必然分叉（DSH 重启/断线时口径就不同了）。
> - `remainingMs` 与 `endsAt` **都给**：跑着时用 `endsAt - now`（本地插值），
>   暂停/未运行时 `endsAt` 为 `null`，必须回落 `remainingMs` ——
>   拿 null 去算会得到荒唐的负数。
> - **`text` 由 Host 格式化**（口径是"向上取整"）：两端各写一套的话，
>   差一秒就会出现"托盘显示 24:59、桌宠下面显示 25:00"，用户以为其中一个坏了。
> - 缺整块（旧 Host）按"没有番茄钟"处理（零回归）。
>
> **`interact` 块的语义（互动信号）**：
>
> - 用**递增 `seq`** 而不是时间戳：同一毫秒内两次互动时间戳相同，exe 会漏掉第二次。
> - exe **只在 `seq` 变化时播一次**语音（`_lastInteractSeq` 去重）。
> - **互动语音由快照驱动，不由点击驱动** —— Host 才是"这次互动算不算数"的
>   判定方（可能在冷却中）。等它把 seq 推回来再播，语音与真实结果才一致。
> - 缺整块（旧 Host）→ 不播互动语音（零回归）。
>
> **`speak` 块的语义（动态语音，v3）**：
>
> - `{seq, name, durationMs, text, utterance}`：AI 回答被合成后的音频，`name` 是缓存键，
>   exe 去 `/pet/speech/<name>` 取字节。
> - `seq` 递增（与 `interact` 同一模式），但 exe **按 `name` 去重** ——
>   Host 重启后 seq 会归零，按 name 去重才不会把同一句重复念一遍。
> - `utterance` = "这是第几句回复"，同一条回复的所有分片共用一个号 →
>   exe 据此**排队续播**（换句才清队列）。
> - 缺整块（旧 Host / 没开动态语音 / 还没合成好）→ exe 保持沉默。
>
> **`speak.fallback` 子块（兜底台词，2026-10-07 新增）**：
>
> ```jsonc
> "speak": { "fallback": { "seq": 7, "event": "chat/reply" } }
> ```
>
> - Host 只在"确实想说话、但运行时合成没兜住"时填它（TTS 子插件没装 / 超时 / 合成失败）。
> - exe 见到**新的 `fallback.seq`** 且 `speak.name` 为空时，播一次 `fallback.event`
>   对应的**固定台词**（清单 `art/voice/voice.json` 里的事件）。
> - ⚠️ **有 `name` 就不播**（否则一句回复说两遍）。
> - 缺该子块（旧 Host / 一切正常）→ 零回归。
> - 为什么需要它：`chat/reply` 有 12 条固定台词，而 exe 此前**没有任何地方**
>   `Speak("chat/reply")` —— 也就是说 TTS 一关，这 12 条就是死资源，
>   而"回复到达"那个时刻**完全无声**（`Speak()` 找不到语音是静默返回，无日志无报错）。

> **`chat` 块的语义（聊天入口）**：>
> - exe 的输入窗靠 `available` 决定"聊天"选项**显不显示** ——
>   **给了入口但点了必失败是最糟的交互**（与 `send` 同一纪律）。
> - `enabled` 与 `available` **分开**：一个表达"宿主不行"，一个表达"用户不要"，
>   `reason` 里区分得开 —— 用户看日志时能分清是环境问题还是自己的设置。
> - 缺整块（旧 Host）→ 只显示"指定对话"（零回归）。

> **`attention` 块的语义（常亮提醒）**：
>
> - **触发**：`approval/asked`（AI 要授权）或 `tool/call` 的 `name === 'ask_user_question'`
>   （AI 在等你回答问题）。`approval` 压过 `question`；同级取最新会话。
> - **气泡随之变为 `kind: "attention"` 且 `bubble.sticky === true`** ——
>   渲染方**不按 `bubble.durationMs` 收气泡**，一切以 `attention` 块为准：
>   块存在就常亮，块变 null 就立刻收起。
> - **兜底上限 30 分钟**（`attentionMaxMs`）：提问的清除依赖 `tool/result`，
>   而真实 tool/result **不带 callId**（只能保守清除）；事件没到时必须自己放下，
>   绝不永久钉在屏幕上。超限会话不再计入提醒。
> - `count` 用于显示"2 项待处理"；`bubble.attentionCount` 同值冗余给渲染方。
> - **缺整块（旧 Host）按 null 处理**（无提醒，零回归）；
>   设置 `attentionReminder: false` 时 Host 恒发 null。

> **`send` 块为什么需要**：气泡里发消息依赖宿主的 `ctx.sessionController` 服务
> （GUI 发消息走的就是它）。它是**异步装配**的，也可能某些 profile 没装配 ——
> 所以两半边都用这一位决定 ✎ 入口**显不显示**：宁可不给入口，也不要给一个
> 点了必报错的入口。**缺该块按不可用处理**（旧 Host 快照零回归）。

> **`settings` 块为什么在快照里**：历史上 exe 只在 spawn 时从 argv 拿一次设置，
> 用户在设置页里改大小/透明度/穿透，原生窗口**毫无反应**，要重启才生效。
> 快照本来就是"推给渲染方的现状"，把 exe 关心的设置放进来，就是一条**已有的**
> 通道 —— 不加新路由、不加新 SSE 帧类型。规则：
>
> - **逐字段 diff，值变了才应用**（避免每帧重复 SetScale 造成抖动）；
> - 缺整块 `settings`（旧快照）= 不动现状，完全向后兼容；
> - **Host 是唯一事实源**：exe 托盘改设置后 POST 回 `/pet/settings`，
>   Host 归一化再广播，exe 收到自己的值（diff 后等于不动）—— 不会打架。
>
> `theme` 的优先级：**argv `--dark 0|1`**（测试用）> `settings.theme` > 渲染方自判
> （exe 读注册表 `AppsUseLightTheme`；overlay 读外壳 `data-ds-theme-source`，
> 读不到退回 `prefers-color-scheme`）。`auto` 即"渲染方自判"。

**SSE 帧格式**（`GET /pet/events`）：

```
retry: 3000\n\n                              ← 首帧，建议重连间隔
event: hello\ndata: {…快照…}\n\n               ← 连上立刻一帧
event: state\ndata: {…快照…}\n\n               ← 之后每次变化
: ping\n\n                                    ← 每 25s 注释心跳（不是事件）
```

**关键**：`data:` 后必须是**单行压缩 JSON**（不能含裸换行）——
C# 侧与 overlay 侧都按「读到空行 = 帧结束」解析。

## 3. HTTP 路由（前缀 `/api/zhuang-fangyi/pet`）

### 3.1 准入：**令牌 或 同源围栏**（两条路径，缺一不可）

这一点与最初的设计不同，是**写浏览器半边时才发现并修正的**，值得记清楚：

| 调用者 | 带令牌？ | 走哪条路径 |
|---|---|---|
| **原生 exe** | ✅ 能带请求头 | `Authorization: Bearer <token>` |
| **浏览器半边** | ❌ **拿不到令牌** | 同源信任围栏 |

**为什么浏览器必须走围栏**：`EventSource` **根本不允许设置请求头**，
所以 SSE（`/pet/events`）在浏览器侧**不可能**带令牌。若强制要求令牌，
窗口内兜底桌宠直接坏掉。

所以判定是：

```
令牌正确                → 放行
否则 且 同源围栏通过    → 放行
否则                    → 403
```

**围栏内容**（照抄本 profile 已验证的 `dsh-our-free-model/src/trust.js`）：
仅 loopback Host、拒 `sec-fetch-site: cross-site`、Origin/Referer 必须同 authority；
组合里有 `connection` 服务时优先用它的 `admit(req)`。

**安全边界（诚实声明）**：围栏挡的是**网页**（跨站读取 / DNS 重绑定）。
它**挡不住本机任意进程**（任何进程都能伪造 loopback Host 并裸发请求）——
这一点与本 profile 的既有事实一致：主题插件的 `/api/zhuang-fangyi/*`
本来就是**无令牌、仅靠 loopback 暴露**的。而桌宠快照**不含任何消息正文**，
只有 `thinking/working/…` 这类状态词，泄漏面很小。

| 路由 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/pet/settings` | GET / POST | `{settings:{…}}` | `{settings:{…}}` |
| `/pet/state` | GET | — | 单个快照 JSON（轮询兜底） |
| `/pet/events` | GET | — | SSE 流（见 §2） |
| `/pet/atlas` | GET | — | `pet.json` 内容 + `report` |
| `/pet/art/<name>` | GET | — | 图片字节；`<name>` 必须在清单白名单内 |
| `/pet/position` | POST | `{"x":100,"y":200}` | `{"ok":true}` |
| `/pet/send` | POST | `{"text":"说点什么","sessionId?":"…"}` | `{"ok":true,"sessionId":"…"}` |
| `/pet/gallery` | GET | — | `{"items":[{file,hasText,opaque,fileDark,group}]}`（画廊用；主动浏览全部表情） |
| `/pet/command` | POST | `{"command":"focus-dsh"\|"reload-art"\|"quit"\|"restart"}` | `{"ok":true}` |
| `/pet/diag` | GET | — | 构建标记、素材报告、launcher 状态 |

> **`/pet/send` 的语义**：把一段文本**排队**投给某个会话，**不打断**当前回合
> —— 这是用户明确选的投递方式。
>
> 实现是 `sessionController.prompt(request, signal)`。这个调用有**两条必填约束**，
> 两条都各自造成过真机上"发送必 502"：
>
> ⚠️ **1. `mode` 是必填字段**，不是可选：上游 zod schema 实测是
> `z.union([z.literal("queue"), z.literal("steer")]).readonly()`，**没有 `.optional()`**。
> `'queue'` = 排在当前回合之后（我们要的）；`'steer'` = 插进当前回合（不要用）。
>
> ⚠️ **2. 第二个参数 `signal` 也是必填的**（且必须是真 `AbortSignal`）。
> 上游把 `prompt` 注册为 `cancellation: { parameter: 'signal' }`，
> 网关按该描述符取**第 2 个实参**并直接调 `signal.throwIfAborted()` —— 少传就是：
>
> ```
> TypeError: Cannot read properties of undefined (reading 'throwIfAborted')
> ```
>
> 这句抛在 `prompt()` **内部**，被路由兜底分支包成 `502 send-failed`。
> 所以**两个都要给**：漏 `mode` 或漏 `signal` 的症状完全一样（502），
> 只有 `message` 字段能区分 —— 这也是为什么下面那条要求渲染方**必须显示原因**。
>
> - `sessionId` 省略时由 Host 挑**最近活跃**的会话（就是桌宠此刻在演的那个）；
> - `sessionId` 由**渲染方从快照 `sessions[].sessionId` 里选**（v5 起带 `title`，
>   所以选择器能显示可读名字）。Host 会**校验**：指定了却找不到该会话 → `409 no-session`，
>   不静默改投别的会话（那会让用户以为发对了地方）。
> - 文本上限 **2000 字**（气泡输入框是快捷入口，不是写长文的地方）；
> - 状态码：`400 empty/too-long`、`409 no-session`、`503 unavailable`（宿主没装配
>   `sessionController`）、`502 send-failed`（投递被拒，带 `message`）。
>
> ⚠️ **`502` 的响应体带 `message`（真正的原因），渲染方必须把它显示出来。**
> 曾经 exe 只显示"发送失败（HTTP 502）"、把 `message` 整段丢掉，
> 代价是"漏传 `signal`"这个 bug 拖了两轮才定位 —— 宿主明明回了
> `Cannot read properties of undefined (reading 'throwIfAborted')`，却被那行吞掉。
> **兜底文案不该吃掉原始原因。**（`pet/PetInput.cs` 的 `DescribeSendError` 已修，
> 并同时写进 `pet.log`。）
>
> - 准入与其他路由一致（令牌 **或** 同源围栏）。

> **`/pet/settings` 是桌宠自己的**（`$DSH_HOME/zhuang-fangyi-pet/settings.json`），
> **不是**主题插件的 `/api/zhuang-fangyi/settings`。两个插件各自独立一份设置，
> 零耦合。把桌宠设置塞进主题插件的设置里会被它的 normalize 丢掉。

> `stats.snapshot()`）。分开是因为**变化频率不同**：成长数据（连续天数、
> 里程碑、7 天趋势）变得很慢，塞进每帧广播等于每次状态变化都重算一遍。
> 但**形状必须一致** —— 两处各挑字段的话，菜单显示 3 天、面板显示 2 天，

> exe 侧夹过一次不代表这里可以信。

> **动态语音（`/pet/speech*`）：把 AI 的回答念出来。**
> 音频由**独立的合成子插件**（`dsh-zhuang-fangyi-voice`）产出，桌宠只依赖它的
> `GET /health` 与 `POST /tts`（详见 `docs/语音子插件对接.md`）。三条硬约束：
>
>   · **异步** —— 气泡先显示文字、语音好了再播，绝不阻塞回复（onnx 后端
>     一句 6 秒的话要 37 秒，同步等它等于聊天卡死）；
>   · **必须能失败** —— 服务不在 / 超时 / 返回非 WAV → 退回固定台词，聊天不受影响；
>   · **缓存键含服务身份**（后端名）—— 换音色后同一句话会自动重新合成。
>     只按文本做键会让换音色后**静默播旧音**（听起来只是"没生效"）。
>
> **合成服务监管（`/pet/speech/service`）**：常驻开关的执行者。
> `start` = 起进程并**等它就绪**（真的等模型加载完）；`stop` = 停掉
> **我们自己起的**（用户自己在终端起的服务绝不终止）；`status` = 只读快照。

### §3.5 `/pet/voices` 的应答形状（两个消费方共用，**不许手拼**）

```jsonc
{
  "available": true,
  "version": 1, "generatedAt": "2026-10-06T05:47:35Z",
  "count": 40,
  "totalMs": 127281, "totalBytes": 1040578,   // ← 面板显示"40 条 / 127s"用的
  "realCount": 11, "synthCount": 29,
  "byEvent": { "pet/click": 5, "turn/complete": 4, "...": 0 },
  "names": ["wake", "click-1", "..."],
  "lines": [                                   // ← 原生 exe 按 event 挑台词
    { "name": "click-1", "file": "click-1.mp3", "event": "pet/click",
      "source": "synth", "durationMs": 2700, "bytes": 172844 }
  ]
}
```

> **为什么必须写成契约**：这个端点有**两个消费方** —— 面板（要 `count`/`totalMs`
> 显示"40 条 / 127s"）和原生 exe（要 `lines[]` 按事件挑一条播）。
> 两边要的字段不同，于是**手拼字段**看起来"各自够用"，实则埋雷：
>
>   · 实测踩过：`/pet/voices` 手拼了 `{version, generatedAt, count, lines}`，
>     **漏了 `totalMs`** → 面板永远显示 **"40 条 / 0s"**
>     （`Math.round(undefined ?? 0)`），而 host 侧其实早算好了 127281ms。
>     更糟的是**测试桩手拼了同一组字段**，两边错得一模一样 → 全绿。
>   · 反过来，若为了"统一形状"只返回诊断用的统计而**丢掉 `lines`**，
>     就是**所有固定语音静默失效**（exe 建不出事件索引），且不报任何错。
>
> 所以规则是：**必须由 `voiceReport()` 单一产出**，它同时带统计与 `lines`；
> `byName`（`Map`，`JSON.stringify` 会变 `{}`）**不得**出现在应答里。
> 消费方改动前先看这张表：加字段可以，删字段要同时改两个消费方。
> 动作走白名单（与番茄钟/互动同一纪律）。
> ⚠️ 与 `/speech/probe` 同一坑：这些**精确匹配分支必须排在
> `/speech/<name>` 之前**，否则 `service` 会被当成"要取名为 service 的语音"。

> ⚠️ `/speech/probe` **必须排在 `/speech/<name>` 前缀分支之前**：否则 `probe`
> 会被当成"要取名为 probe 的语音"，表现为 404 —— 而且看起来像"服务没起"。
> ⚠️ `name` 只允许 `^[0-9a-f]{16}$`（缓存键形状）。这是纵深防御：
> 路由**不解码**百分号编码，所以穿越串到不了读盘那层；但白名单保证
> "非法形状的文件即使存在也不给"（e2e 里种了非法名的真实文件来验证这条）。

> **人设是"加法"的：共享背景 + 语言风格。**
> 目录结构：
> ```
> personas/
>   shared/            ← 共享背景（世界观/身份/称呼/锚点/准则），按文件名序**全部拼接**
>     庄方宜-背景.md
>   default.md         ← 语言风格（只写"她怎么说话"，不重复世界观）
>   严谨.md            ← 另一种风格
> ```
> 最终人设 = `shared/*.md` + 所选风格。**没有 `shared/` 时行为完全不变**
>（旧式自包含人设兼容）。两条路（系统提示词 section 与 AGENTS.md 兜底）
> **都写组合后的文本** —— 否则同一个角色在两台机器上表现不一致。
>
> 为什么这么设计：用户的原话是"基于通用的世界观提示词加上不同的语言风格"、
> "可以在设置中共享"。世界观改一次要能影响所有风格，而不是复制 N 份。

> **`/pet/memory` 是整体替换，不是追加。**
> 设置页给的是一个文本框，用户按保存就该看到自己写的那份；
> 追加语义会让"删掉一行"变成不可能。空字符串是**合法输入**（= 清空）。
>
> **跨会话共享的机制**：记忆是一个文件
> （`$DSH_HOME/zhuang-fangyi-pet/memory.md`），以 `zf-pet:memory` 这个
> section 名字注入到**每个**聊天会话的 agent 作用域 —— 换会话、重开会话都跟着走。
> 自动提炼（`memoryAuto`）用宿主默认模型把每轮里值得长期记住的事追加进去
>（`ctx.llm.stream`，消息形状照抄宿主 `createUserMessage`）；
> 文件超上限（24KB）时**裁掉最旧的行**（记忆是滚动的，不是无底洞）。

> **动作名一律走白名单，且校验放在路由层。**
> 番茄钟的 `action`、互动的 `kind`、语音的 `name`、人设的 `name` 都**绝不允许
> 透传到内部**。回退验证抓到过两处真实缺口：
> · 互动路由原先只靠 `do()` 返回 null 兜底 —— 删掉路由层白名单后测试**全绿**，
>   而 `__proto__` 这种原型链名字已经进了内部；
> · 语音路由原先不检查 HTTP 方法，`POST /pet/voice/<name>` 也能读到文件。
>
> 教训：**白名单要在"串进入内部之前"生效**，不能靠下游返回 null 兜底 ——
> 那是"看起来有防线、实际靠巧合"。

> **`/pet/voice/<name>` 只查白名单，不拼路径。** 清单里没有的名字一律 404，
> 路径根本不参与拼接（比"拼完再检测 `../`"更稳）。纵深防御有三层：
> `isSafeName`（字符白名单）→ 先拒绝对路径/盘符 → 解析后再确认落在目录内。
> 第二层是回退验证逼出来的：`C:\Windows\win.ini` 能绕过 `startsWith(root)` 判断，
> 因为 `path.join(root, 'C:\\...')` 在 Windows 上返回的就是那个绝对路径本身。

> **`/pet/chat` 不复用 `/pet/send`。** `/pet/send` 是"发到**某个已有**会话"
> （用户从列表里挑一个），而聊天是"发到**我们自己的**会话" ——
> 它会按需创建工作区与会话，语义完全不同。两条路的状态码一致
> （`400 empty/too-long`、`409 no-session`、`503 unavailable`、`502 send-failed`
> 且**带 `message`**）。

> **`/pet/personas` 的写入安全约束**（`src/pet/persona.js`）：
> 切换人设会写工作区的 `AGENTS.md`，而那是**磁盘上的文件** ——
> 所以：① **绝不覆盖用户手写的**（判据是"我们的标记必须在**第一行**"，
> 放宽成"含这个字符串"会把引用过标记的用户文件误判成我们的产物然后覆盖）；
> ② 人设名走字符白名单（它会被拼成路径）；③ 磁盘上的 `default.md`
> **覆盖**内置那份（磁盘优先、内置兜底）。

> **`x/y` 只属于原生窗口**。窗口内 overlay 用**视口坐标**、原生窗用**桌面坐标**，
> 混写到同一组字段会互相覆盖导致位置乱跳。overlay 自己记 `localStorage`。

**其余两道围栏**：
2. **一次性令牌**：每次 spawn 由 Host 用 `crypto.randomBytes(24).toString('hex')` 生成，
   经 argv 传给 exe，**不落盘**，常量时间比较。
3. **素材白名单**：由 `pet.json` 派生，**绝不拼接客户端传入的路径**，
   并二次校验 `path.resolve` 仍在 `art/pet` 内（照抄主题插件 `artWhitelist()` 的双保险）。

## 4. 素材清单 `art/pet/pet.json`

**这是 Host 与 exe 之间关于素材的唯一契约。**
`frameHeight` 是产出时的实际帧高；exe **不得假设固定值**，必须按此缩放。

> ⚠️ **单帧不是方的**（实测 204~288px 宽，取决于素材内容 bbox 的纵横比 0.85~1.13）。
> 所以**绝不能**拿 `frameHeight` 当单帧宽度 —— 那会把图横向压扁，并在切状态时
> 宽度跳变。两侧都必须：
>   · **优先用图片实测值**（`naturalWidth / frames`）；
>   · 加载前用清单里的 `frameWidth` 占位；
>   · 最后才回落到 `frameHeight`。
>
> 条带的宽度**不是** `frames × frameHeight`，而是 `frames × frameWidth`。

```jsonc
{
  "version": 1,
  "generatedAt": "2026-10-04T14:00:00.000Z",
  "frameHeight": 256,                          // 所有条带的实际帧高（一致）
  "states": {
    "idle":   { "file": "idle.png",   "frames": 1,  "frameWidth": 284, "frameMs": 0, "anchorY": 1.0 },
    "happy":  { "file": "happy.png",  "frames": 33, "frameWidth": 256, "frameMs": 30 }
  },
  "variants": {
    "idle": ["idle.png", "idle-2.png"]        // 同状态多素材轮换；states 里的必须在其中
  },
  "files": {                                   // ⭐ 每个文件**自己的**几何
    "idle.png":   { "frames": 1,  "frameWidth": 284, "frameMs": 0  },
    "idle-2.png": { "frames": 4,  "frameWidth": 256, "frameMs": 60 },
    "happy.png":  { "frames": 33, "frameWidth": 256, "frameMs": 30 }
  },
  "bubble": [
    { "file": "bubble/01.png", "w": 240, "h": 240 }
  ],
  "missing": [
    { "name": "表情包_08_爱你哦", "reason": "needsCutout", "detail": "四角纯白、完全不透明" }
  ]
}
```

- `states` 的键**只能是 §1 的状态名**；缺某个状态时 Host 回落到 `idle`。
- `file` 是相对 `art/pet/` 的路径，**必须**同时出现在 Host 的 URL 白名单里。
- **`frameWidth`（每帧的像素宽）是必需字段**：单帧非方形，两侧都需要它才能
  在图片加载前算对布局。
- **`variants` 是文件名数组**（不是对象），保持稳定。
- **`files` 是必需字段**（v1 起）：覆盖 `states` + `variants` 引用到的**每一个**文件，
  给出该文件**自己的** `frames` / `frameWidth` / `frameMs`。

  > **为什么必须有 `files`**：`variants` 里的素材**几何差异极大** ——
  > 实测 24 个变体里 **14 个**与所属 state 的声明不符，因为变体混了
  > 「静态 PNG（1 帧）」与「动态 GIF（N 帧）」：
  > `happy` 声明 33×256，而 `happy-2.png` 是 274px（1 帧）、`happy-4.png` 是 239px（1 帧）。
  > 若按 state 声明的 `frames` 去切变体，`happy-4.png` 会变成 `239/33 = 7px` 的**碎条**。
  >
  > **几何解析优先级（两侧都必须按此顺序）**：
  > ```
  > files[<文件名>]  →  states[<state>]  →  图片实测（naturalWidth / frames）
  > ```
  > `files` 缺失时回落后两级，**旧清单仍可用**。

- **产物命名：主体条带 = `<state>-<id>.png`（`<id>` 是素材台账里的语义键）**。
  例：`idle-smile.png`、`thinking-starry-formula.png`、`error-listless.png`。
  **canonical（`states[x].file`）同样是这个形式**，不再是 `<state>.png`。

  > **为什么 2026-10-07 改成带语义 id**：原先按位置编号（`idle.png` / `idle-2.png`…），
  > 于是看文件名认不出画的是什么，清单里也没有字段能对上号 ——
  > 测试只能"数张数"（`variants.happy.length === 8` 这类断言），素材一换版就红，
  > 且看不出哪张挪去了哪。带 id 之后断言可以**按名字写**，以后再挪图不用改测试。
  >
  > ⚠️ **两侧都不得解析文件名**：`file`/`variants` 是唯一真相，
  > exe 与 overlay 一律按清单里的路径取图（这条规矩本轮没变）。

- **`assets` 是可选的附加段（v-next）**：产物路径 → 身份（语义 id / 画面说明 / 归属）。
  纯附加字段，**旧清单没有它照常工作**（两侧应容忍缺失，而不是报错）：

  ```jsonc
  "assets": {
    "error-listless.png":     { "id": "listless", "role": "body", "family": "F5",
                                "caption": "无精打采 + 吐彩虹", "mood": "dead",
                                "states": ["error"] },
    "bubble/new/13-so-good.png": { "id": "13-so-good", "role": "bubble", "family": "F4",
                                "hasText": true, "opaque": true, "random": true,
                                "keys": ["happy", "notify-complete"] }
  }
  ```

  > 它由 `assets/catalog.json`（素材台账，唯一真相）派生。诊断（`/pet/diag`）
  > 与 e2e 断言都靠它把"文件名"和"画的是什么"对上号。
  > ⚠️ `/pet/atlas` **必须透传该段** —— `files` 字段曾因为只在这一跳被吃掉而
  > 静默失效过（宿主自检直接读 `pet.json` 是绿的，走 HTTP 却缺字段）。

- `bubble` 是气泡表情池。每项除 `file`/`w`/`h` 外，**必须**给出 `hasText`，并**可选**给出
  `opaque`、`fileDark` 与 `frames`/`frameMs`：

  ```jsonc
  "bubble": [
    // 透明抠图（贴纸线条之外是透明）：需要气泡自己的底/内边距
    { "file": "bubble/17-yay.png",  "w": 256, "h": 262, "hasText": true,  "opaque": false },
    // 不透明满幅贴纸（自带白底/黑底，铺满整图）：**不要**再套气泡底
    { "file": "bubble/new/01.png",  "w": 256, "h": 256, "hasText": true,  "opaque": true },
    // 动态气泡（33 帧 GIF）：渲染方解出全部帧并按 frameMs 推进
    { "file": "bubble/starry-formula.gif", "w": 256, "h": 256, "hasText": false,
      "opaque": true, "frames": 33, "frameMs": 30 }
  ]
  ```

  > **`frames` / `frameMs` 的语义（v-next）**：这张气泡是**动图**，`frames` 是帧数，
  > `frameMs` 是**统一**帧间隔（不是每帧各自的延时 —— 与 `states[].frameMs` 同一套约定）。
  >
  > **为什么需要**：素材里有两段「整段动画都有实心帧」的 GIF（`05_星空公式` /
  > `27_生气指人`）。它们不能当**主体动画**用（判据 `min_transparent_ratio`：只要有一帧
  > 铺满不透明像素，播到那一帧桌面上就是个矩形色块），但**当气泡完全没问题** ——
  > 气泡本来就是卡片/贴纸，满幅不透明正是它的语义（见下面 `opaque`）。
  > 所以**整段原样交付**：不抠图、不挑帧。
  >
  > **渲染方要求**：
  >   · `frames <= 1` 或字段缺失 → 按静态图处理（**旧清单零改动仍可用**）；
  >   · `frames > 1` → 解出全部帧并按 `frameMs` 推进；**静态气泡严禁**走这条路径
  >     （白白解一遍全部帧）；
  >   · 先按 `w`/`h` 上限缩放再播（实测 33 帧 500×500 不缩放约 33MB，缩到 256 约 8MB；
  >     缩放不改变布局 —— 气泡图片本来就有尺寸上限 + Uniform）；
  >   · 气泡收起时必须**停掉帧推进**（气泡窗是长生命周期对象，不停就是后台空转）。
  >
  > **已知降级**：overlay（窗内 HTML）冻结，只显示首帧；动图能力只在原生窗。
  > 这是**有意为之**（overlay 只修 bug、不加功能），不是 bug。
  >
  > `/pet/art/` 必须**按扩展名**给 MIME（`.gif → image/gif`），不能硬编码 `image/png`。
  >
  > 缺该字段时按 `1` / `100` 处理。

  > **`hasText` 的语义**：该图片**本身已经把文字画进去了**（聊天贴纸）。
  >
  > **为什么必须有**：素材里有一整类「带 baked-in 中文文字」的贴纸
  > （实测 16 张，如「好耶！」「工作中…」「爱你哦」）。它们当**主体**会让桌宠
  > 一直挂着同一句话；而当**气泡**时，如果 Host 又叠一句 `bubble.text`
  > （"正在调用工具…"），**屏幕上会出现两段互相打架的文字**。
  >
  > 所以规则是：**`hasText === true` 的气泡图，`kind` 必须是 `'image'`（不叠文字）**。
  > `hasText === false` 的图可以配文字，`kind` 取 `'both'`。
  >
  > 缺该字段时按 `false` 处理（旧清单仍可用，只是可能叠字）。

  > **`opaque` 的语义**：该图片**没有 alpha、铺满整个画布**（线稿贴纸自带白底）。
  >
  > **为什么需要**：素材里有一批「黑白线稿 + 白底铺满整图」的贴纸（实测 20 张）。
  > 它们**不能抠白底** —— 实测白色既是背景**也是脸/衣服的填充色**，键控白底会把
  > 角色内部一起掏空（实测透明占比 73~79%，脸上会破出透明洞）。
  >
  > 但它们的呈现方式与透明抠图不同：**不要再套气泡自己的背景/内边距/圆角**，
  > 否则会出现「一张白纸贴在另一个浅色框里」的双层边框。
  >
  > 缺该字段时按 `false`。

  > **⭐ 气泡外壳的规则（v-next 起）：按"内容"决定，不按图片的 alpha 决定**
  >
  > 用户提了一个很到位的问题："表情做气泡内容的时候，为什么一定要加个白底？
  > 白底可以去掉啊"。答案是对的 —— **白底的唯一用途是让文字可读**：
  >
  > | 气泡内容 | 外壳 | 为什么 |
  > |---|---|---|
  > | **纯图片**（贴纸 / 动图 / 满幅） | **不画**（无底、无边框、无内边距） | 图片自己就是内容；垫白卡只会多出双层边框 + 白占一圈内边距 |
  > | **有文字** | **必须画**（底色 + 边框 + 内边距 + 圆角） | 否则字直接飘在桌面上，深色壁纸下看不清 |
  > | `kind: 'attention'` | 恒走卡片（有自己的描边/头部条） | 贴纸语义不适用于提醒气泡 |
  >
  > 所以渲染方的判据是 **`有图 && 无文字` → 不画外壳**，而**不是**看 `opaque`：
  > `opaque` 只是"这张图本身满幅"的**素材属性**（决定要不要裁圆角、要不要放宽图片上限），
  > 现在"纯表情也不垫白卡"是更一般的规则。
  >
  > **没有外壳 ≠ 没有投影**：图片直接贴在壁纸上时，靠**投影**才能浮起来、
  > 不至于糊进背景（白卡原本顺带提供了这层边界感）。所以投影在两种模式下都保留。
  >
  > 兼容性：`opaque === true` 的气泡仍然不画外壳（行为不变）；变化只发生在
  > `opaque === false` **且无文字**的那些 —— 它们从"白卡里的贴纸"变成"直接贴的贴纸"。

  > **`fileDark` 的语义**：深色模式下的变体（**可选**；缺省 = 深色模式也用原图）。
  >
  > ⚠️ **v7 起：本插件不再产出任何 `fileDark`，深色模式直接用原图。**
  > 用户实测反馈："深色模式气泡表情反转太诡异了，直接原图还挺好的"、
  > "深色模式不用单独的表情包"。
  >
  > 原因是结构性的，调算法救不回来：那批黑白线稿贴纸是**白纸上的墨线**，
  > 白色不只是背景、**还是脸和衣服的填充色**。翻明度之后整张脸变黑、
  > 只有轮廓发白 —— 那是**底片**（照片负像），不是"深色贴纸"。
  >
  > **字段本身保留**（不删），因为它是可选字段且缺省语义恰好就是"用原图"——
  > 删掉会破坏向后兼容（旧清单、exe 侧 `ImageDark`、overlay 侧 `imageDark`
  > 都必须能继续解析）。所以：
  >
  > - **渲染方**：照旧实现 —— 深色且 `fileDark` 非空才换图，否则用 `file`。
  >   这对本插件的清单等价于"永远用 `file`"，但对**旧清单**仍能正确工作。
  > - **管线**：不再生成 `-dark.png`（`prepare-pet.py` 会核对并报告异常）。
  >
  > 历史生成规则（已停用，留档）：对**低饱和像素**翻明度、保留高饱和像素的色相；
  > 整通道取反会把彩色点缀补色化（粉爱心→青绿、黄星星→蓝），实测 5/20 张明显偏色。

- `missing` 列出待人工抠图的素材；**缺失不得导致任何一方报错**。

## 5. exe 启动契约（Host → exe）

Host 用 `ctx.subprocess.spawn` 启动（**不用 `node:child_process` 绕过**）。

```
argv: [<exe路径>,
       --url http://127.0.0.1:<port>     // 基址，见 §0
       --token <48位hex>                 // 一次性令牌，见 §3
       --state <petState>                // 启动瞬间的状态（避免首帧闪错）
       --scale <float>                   // 0.5~2.0
       --opacity <float>                 // 0.3~1.0
       --x <int> --y <int>               // 上次位置；缺省=主屏右下角
       --topmost <0|1>
       --click-through <0|1>
       --bubble <0|1>
       --voice <0|1>                     // ⭐ v8：语音总开关（**默认 0**）
       --selftest                        // 无窗口自检；退出码 0=通过
```

> ⚠️ **argv 是"启动瞬间"的值，不是唯一真相。** 用户在设置页改的东西走
> `snapshot.settings` 实时应用（见 §2）。`--voice` 只是**启动初值** ——
> 漏传它的症状是"设置页开了语音但没声音"，因为 exe 是独立进程，
> 它读不到 `settings.json`，只认 argv 与快照。
> `tools/test-pet-native-e2e.mjs` 专门断言了这个参数真的被传下去
> （那一套测试的整个存在理由就是"两边各自都对、接起来不对"）。

`SubprocessSpawnSpec`（**实测契约**）：

```ts
{ argv: readonly string[], cwd: string, stdio: SubprocessStdio, graceMs: number,
  signal?: AbortSignal, env?: NodeJS.ProcessEnv }
// stdio: { stdin:'ignore', stdout:'pipe', stderr:'pipe' }
// handle: { stdin, stdout, stderr, collected, done: Promise<{exitCode, signal}>,
//           terminate(): void, waitForExit(signal?): Promise<boolean> }
```

**exe 侧硬要求**：
- **命名互斥体** `Global\DSH-ZhuangFangyi-Pet`；已被占用 → 立即 `exit(0)`（避免多只桌宠）。
- **连续 5 次 401 → 主动退出**（宿主重启后不留连不上旧令牌的僵尸）。
- 退出码约定：`0` 正常；`1` 自检失败；`2` 互斥体被占；`3` 参数非法；`4` 素材缺失。
- 宿主侧：exe 在 `t < 10s` 内非零退出 → **不自动重启**，置 `nativeError` 并在 `/diag` 暴露。

## 6. 素材转场（不变式）

- **绝不读会话消息正文**（文档 §十 红线）：只消费事件元数据与 `turn/end` 的 `reason.kind`。
- **透明底必须保留 alpha**：PNG RGBA，绝不 `flatten()`，否则透明区残留 RGB 变彩色噪点。
- **按状态懒加载**：12 张 GIF 合计 ~12MB，绝不能全部预加载；一次只解码当前状态那一张条带。
- 精灵图是**横向条带**（`frames × frameHeight` 宽），一份产物同时喂
  WPF（`CroppedBitmap` 取帧，**已实测可用**）与 overlay（CSS `animation: steps(N)`）。
