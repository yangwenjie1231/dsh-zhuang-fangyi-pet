# 语音合成子插件 · 对接说明

> 面向 [`dsh-zhuang-fangyi-voice`](https://github.com/yangwenjie1231/dsh-zhuang-fangyi-voice)（v1）
> 与 [`dsh-zhuang-fangyi-voice-v2`](https://github.com/yangwenjie1231/dsh-zhuang-fangyi-voice-v2)（v2，三种语气）。
> 桌宠这边**已经准备好了**：装好语音插件即自动接管，无需改代码。

---

## 一、三种接法（桌宠自动选）

桌宠启动时（其实是**每次合成时**）按顺序探测宿主上的服务名，用第一个可用的：

| 顺序 | 服务名 | 谁管进程 | 桌宠做什么 |
|---|---|---|---|
| 1 | **`zfhVoiceV2`** | 语音插件 v2 | 调 `synthesize(text, style)` + `styles()`；设置页的三种语气生效 |
| 2 | `zfhVoice2` | 语音插件 v2（短别名） | 同上 |
| 3 | **`zfhVoice`** | 语音插件 v1 | 调 `synthesize(text)`；**只有正常说话**（v1 会忽略 `style`） |
| 都没有 | — | 你自己 / 桌宠兜底 | 走 HTTP `POST /tts`；没配启动命令就只连不管 |
| 连 HTTP 都没有 | — | — | 退回固定台词，**聊天完全不受影响** |

**为什么 v2 要另起一个服务名**：v2 挂 `zfhVoiceV2`，**故意不抢** `zfhVoice` ——
这样 v1 的调用方（包括旧版桌宠）一个都不受影响，两版可以**同时装着**（8765 / 8766）。

**想换回 v1 怎么办**：在插件管理器里**停用 v2 那一条**即可。
`ctx.get` 是每次现查的，所以**下一次合成**就走 v1 —— 不需要重启 DSH，
桌宠这边也没有"用哪个插件"的设置项（那等于把插件管理器的开关再实现一遍）。

设置页「合成服务」那一行会写明当前是哪种：`由语音插件托管`（并写明**哪一个**服务名）/
`运行中（桌宠启动的）` / `运行中（你自己启动的）` / `未运行`。

## 二、桌宠调用什么

装了 v2 时（服务面）：

```js
const voice = ctx.get('zfhVoiceV2')
await voice.synthesize('做完了，你看看。', 'firm')   // → {bytes, durationMs, backend, style} | null
await voice.synthesize('做完了，你看看。')            // style 省略 → 用插件配置里的（默认 normal）
await voice.styles()                                 // {current, styles:[{name,label,available,…}]}
await voice.setStyle('gentle')                       // {style, applied}
voice.status()                                        // 只读状态
voice.start() / voice.stop()                          // 显式控制
voice.configure({resident, idleStopSec, idleAction, style})   // 桌宠把设置页的开关推给它
```

装了 v1 时（服务面）：同上，但 `synthesize(text)` 没有第二个参数，也没有
`styles()`/`setStyle()`。桌宠**用能力探测**（有没有 `styles`/`setStyle`）判断支不支持风格，
而不是按服务名判断 —— 将来的第三版只要还提供这两个方法就自动可用。

没装插件时（HTTP，即语音插件 Python 侧的契约）：

| 用途 | 请求 | 期望响应 |
|---|---|---|
| 健康检查 | `GET /health` | `{"ok":true,"backend":"torch"\|"onnx","version":"…"}` |
| 合成一句 | `POST /tts`，body `{"text":"……"}` | **`audio/wav` 二进制**（RIFF 头） |
| 合成一句（指定语气） | `POST /tts`，body `{"text":"……","style":"firm"}` | 同上（v2 才认 `style`，v1 忽略它） |
| 风格清单 | `GET /styles` | `{"ok":true,"current":"normal","styles":[…]}`（v2 才有） |

### 桌宠对响应的三条硬要求

1. **必须是 RIFF/WAV** —— 否则整条结果被丢弃；
2. **单条不超过 8 MB** —— 超过即丢弃（防"服务返回一整个音频文件"把磁盘写爆）；
3. `Content-Length` 正确（或正常分块）。

不满足时桌宠**静默退回固定台词**，聊天不受影响，日志里记一行。

## 三、语气风格（v2）—— 三条容易搞错的规则

### 1. `normal` 就是 v1：不带 `style` = 带 `style=normal`

实测 `ref/styles/normal.wav` 与 `ref/default.wav` 的 **SHA256 完全相同**。
所以桌宠的策略是：**风格为 `normal` 时不发 `style`**。
两个好处：

- 升级到 v2 之后**声音一模一样**，除非用户主动去改风格；
- **既有语音缓存全部继续有效**，不会因为升级而把已缓存的句子重新合成一遍。

对应地，桌宠的缓存键后缀也只在**非 normal** 时才加 —— 两处用的是**同一个判据**
（`src/pet/tts.js` 的 `styleTagOf()`），分成两处判断迟早会漂移成
"body 带了 firm、键还是旧的"，那就是"换了风格却命中旧缓存"（听起来只是"没生效"）。

### 2. 风格文件缺失时，Python 侧**静默退回 normal**（不报错）

`styles.resolve_style()` 的兜底链是 `ref/styles/<名>.wav` → `ref/styles/normal.wav`
→ `ref/default.wav`。所以某个风格的参考音频缺失时，合成**照常成功**、
只是语气没变 —— 用户会以为"这个开关是假的"。

**唯一知道真相的地方**是 `GET /styles` 返回的 `available`
（它来自 `list_styles()`：只有 `resolved == key` 才算可用）。
所以桌宠在**「试一句」**里取它，并把这句结论直接写在设置页上：

- 可用 → `风格=firm（语气强硬）可用`
- 不可用 → `⚠ 风格=firm 不可用（缺参考音频）—— 插件会静默退回「正常说话」`

（`GET /pet/speech` 是**同步**接口、不查清单，所以它只报
`style` / `styleSupported`（能力）/ `provider`（哪一个服务名）；
"某一档到底可不可用"在 `/pet/speech/probe` 里给。）

### 3. 装了 v1 却选了非 normal —— 声音正常，语气不变

v1 的 `normalizeConfig` 只认白名单键，`style` 会被**静默丢弃**；
它的 Python `/tts` 也只读 `text`/`seed`/`brightness_db`。
所以这是**预期行为**（不是 bug），但必须让用户看见：
设置页那一行有说明文字，诊断卡会写 `⚠ 当前插件不支持风格`。

## 四、桌宠侧的开关（设置页 → 语音）

| 设置 | 默认 | 说明 |
|---|---|---|
| `speakReplies` | **关** | 把 AI 的回答念出来。关着时**完全不调用**合成 |
| `voice` | **关** | 语音总开关；它关着时即使 `speakReplies` 开着也不合成 |
| `ttsStyle` | `normal` | **语气风格**：`normal` / `firm` / `gentle`（要 v2 才有效） |
| `ttsResident` | **关** | **常驻**：一直占显存但合成立刻开始；关：空闲后释放显存 |
| `ttsIdleStopSec` | `300` | 非常驻时空闲多少秒释放（0 = 不停） |
| `ttsIdleAction` | `''` | 空闲时怎么释放：`stop`（杀进程）/ `unload`（只卸模型）/ 空 = 插件默认 |
| `speechMaxChars` | `60` | 每段朗读上限（整段都会念完，这个值只决定"多久开口"） |
| `ttsUrl` | `http://127.0.0.1:8765` | 走 HTTP 那条路时的地址 |
| `ttsPython` / `ttsRepoDir` / `ttsBackend` | 空 = 自动 | 走 HTTP 且要桌宠托管进程时才用 |

设置页有三个按钮：**试一句**（真合成并播放，验证链路）、
**启动服务**、**停止并释放**（立刻起/释放，不等空闲超时）。

> ⚠️ **桌宠只推"用户真的设了"的键** —— 其中一条容易看漏：
> `ttsUrl` 的默认值是非空的，所以**默认地址不会**被当成"用户指定了端口"
> 推给插件。这一点是必须的：v2 的默认端口是 **8766**，而
> `ttsUrl` 的默认值是 **8765**（v1 的）—— 无脑推过去会把 v2 顶到 v1 正占着的端口上，
> 两版并存立刻崩掉一个。只有用户**显式改过**地址时才推 `port`。

> ⚠️ **桌宠里没有任何绝对路径**。语音插件的位置按这个顺序找：
> 设置 → 环境变量 `DSH_ZFH_VOICE_DIR` / `ZFH_VOICE_DIR` → **与桌宠同级的
> `node_modules`**（DSH 插件管理器装的话就在那儿）→ 并排签出的目录。
> python 同理：设置 → `ZFH_VOICE_PYTHON` → 仓库里的 `.venv` → PATH。
> 所以同一份配置在任何人的机器上都能用。

## 五、端到端链路

```
AI 回复（markdown）
   ↓ 清洗：去代码块/链接/markdown 标记/emoji，截到句子边界
可朗读文本
   ↓ zfhVoiceV2.synthesize(text, style)（或 HTTP POST /tts），异步、fire-and-forget
WAV 字节
   ↓ 落盘 $DSH_HOME/zhuang-fangyi-pet/speech/<16位缓存键>.wav
快照 speak: {seq, name, durationMs, style}
   ↓ exe 发现 seq 变化 → GET /pet/speech/<name>
播放
```

设计要点：

- **异步**：气泡先显示文字，语音好了再播。onnx 后端一句 6 秒的话要 37 秒，
  同步等它等于聊天卡死；
- **缓存键 = 文本 + 服务身份（后端名 + 风格）**：换后端或换语气后同一句话会自动
  重新合成（只按文本做键会让换了之后仍播旧的，而且毫无报错）；
  ⚠️ 风格为 `normal` 时**不加**后缀 —— 见 §3.1；
- **`name` 会因风格而变，这是必需的**：exe 按 `name` 去重，
  键不变的话"改了风格再点试一句"会一声都不出，用户只会认为"这个功能没做"；
- **代际丢弃**：连发几条时，先发的那句合成完若已过期就丢弃（不盖住更新的那句）；
- **exe 按 `name` 去重**（不是 `seq`）：宿主重启后 seq 归零，按 name 去重
  不会把同一句重复念一遍。

## 六、日志里怎么确认它在工作

`$DSH_HOME/zhuang-fangyi-pet/boot.log`：

| 行 | 含义 |
|---|---|
| `语音合成：zfhVoiceV2（风格支持：是）· 风格=firm` | **谁在服务宿主**（只在变化时记一行） |
| `语音合成：zfhVoice（风格支持：否）· 风格=normal` | 现在是 v1 在管（风格不会生效） |
| `动态语音就绪（新合成 · firm，2400ms，第 1/3 段）：做完了…` | 合成成功并已交付 exe（风格写在括号里） |
| `动态语音就绪（缓存 · firm，2400ms）` | 命中缓存，没重复合成 |
| `动态语音合成不可用 → 第 1/3 段起放弃` | 服务没起 / 超时 / 返回非 WAV |
| `动态语音探测成功，已交付 exe 播放（风格=firm）` | 「试一句」成功 |

语音插件侧（宿主日志）：`庄方宜语音：已挂载 zfhVoiceV2 服务`、
`庄方宜语音：服务就绪（38s，backend=torch）`、`已停止服务（释放显存）`。

exe 侧（`%LOCALAPPDATA%\DSH-ZhuangFangyi-Pet\pet.log`）：
`动态语音播放: <name>（2400ms）`。

## 七、后端选择（直接影响体验）

| | RTF | 6 秒音频 | 占显存 |
|---|---|---|---|
| **torch** | ≈ 0.45 | 约 3 秒 | 要（几 GB） |
| **onnx** | ≈ 6.1 | **约 37 秒** | 不要 |

> ⚠️ onnx 后端逐句交互基本不可用（37 秒后气泡早消失了）。
> 有显卡就用 `torch`。若只能用 onnx，把「每段朗读字数」调到 20~30 字。

安装步骤与排错见语音插件仓库的 `docs/安装提示词.md`
（那份文档可以**整段复制给 AI 助手**，让它替你配好环境）。
