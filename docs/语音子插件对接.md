# 语音合成子插件 · 对接说明

> 面向 [`dsh-zhuang-fangyi-voice`](https://github.com/yangwenjie1231/dsh-zhuang-fangyi-voice)。
> 桌宠这边**已经准备好了**，等子插件可用时打开开关即可，无需改代码。

---

## 一、桌宠调用什么

桌宠只依赖**两个 HTTP 接口**（就是子插件 README 里已文档化的那两个）：

| 用途 | 请求 | 期望响应 |
|---|---|---|
| 健康检查 | `GET /health` | `{"ok":true,"backend":"torch"|"onnx","version":"…"}` |
| 合成一句 | `POST /tts`，body `{"text":"……"}` | **`audio/wav` 二进制**（RIFF 头） |

桌宠**不做**的事：不解析后端类型以外的字段、不调 `/tts.json`（除非 `/tts` 不存在）、
不关心模型目录、不传 `seed`（保持服务默认）。

### 桌宠对响应的三条硬要求

1. **必须是 RIFF/WAV** —— 否则整条结果被丢弃（`x-content-type-options: nosniff` 那类严格性）；
2. **单条不超过 8 MB** —— 超过即丢弃（防"服务返回一整个音频文件"把磁盘写爆）；
3. **`Content-Length` 正确**（或正常分块）—— 桌宠按流读完就写盘。

不满足时桌宠**静默退回固定台词**，聊天不受影响，日志里记一行 `TTS 合成返回 …`。

## 二、桌宠侧的开关（设置页 → 语音）

| 设置 | 默认 | 说明 |
|---|---|---|
| `speakReplies` | **关** | 把 AI 的回答念出来。关着时**完全不调用**合成服务 |
| `ttsUrl` | `http://127.0.0.1:8765` | 只接受 `http://` / `https://` |
| `speechMaxChars` | `60` | 单句朗读上限（清洗后截断到句子边界） |
| `voice` | **关** | 语音总开关；它关着时即使 `speakReplies` 开着也不合成 |

设置页里有个 **「试一句」** 按钮：真去合成并播放一句「嗯，我在呢。」，
把结果与耗时直接写在下面 —— 这是判断"子插件到底通没通"最快的方式。

## 三、端到端链路

```
AI 回复（markdown）
   ↓ 清洗：去代码块/链接/markdown 标记/emoji，截到句子边界
可朗读文本
   ↓ POST /tts（异步，fire-and-forget）
WAV 字节
   ↓ 落盘 $DSH_HOME/zhuang-fangyi-pet/speech/<16位缓存键>.wav
快照 speak: {seq, name, durationMs}
   ↓ exe 发现 seq 变化 → GET /pet/speech/<name>
播放
```

几个设计要点：

- **异步**：气泡先显示文字，语音好了再播。合成慢（onnx RTF 6.1 ≈ 37 秒/句）
  也不影响聊天体验；
- **缓存键 = 文本 + 服务身份**（`backend`）：换音色/后端后同一句话会自动重新合成
  （只按文本做键会让换音色后仍播旧音，且毫无报错）；
- **代际丢弃**：连发几条时，先发的那句合成完若已过期就丢弃（不盖住更新的那句）；
- **exe 按 `name` 去重**（不是 `seq`）：Host 重启后 seq 归零，按 name 去重
  不会把同一句重复念一遍。

## 四、日志里怎么确认它在工作

`$DSH_HOME/zhuang-fangyi-pet/boot.log`：

| 行 | 含义 |
|---|---|
| `动态语音就绪（新合成，2400ms）：做完了…` | 合成成功并已交付 exe |
| `动态语音就绪（缓存，2400ms）` | 命中缓存，没重复合成 |
| `动态语音合成不可用 → 退回固定台词` | 服务没起 / 超时 / 返回非 WAV |
| `动态语音已过期（有更新的回复）→ 丢弃` | 代际丢弃（正常） |
| `宿主没有 llm 服务…` | 与语音无关（那是记忆提炼的降级日志） |

exe 侧日志（`%LOCALAPPDATA%\DSH-ZhuangFangyi-Pet\pet.log`）：
`动态语音播放: <name>（2400ms）`。

## 五、当前状态（2026-10-06）

- 子插件仓库已有 `server.py` / `api.py` / CLI，但**模型未下载、包未安装**；
- 因此桌宠侧用**假合成服务**（复刻上述契约）做了端到端验证：
  清洗 → 合成 → 落盘 → 快照交付 → 字节可取，整条链路 65 项断言；
- 子插件就绪后，只需：`python -m zfh_voice serve --port 8765`，
  然后在设置页打开「念出回答」+「语音」总开关，点「试一句」确认。

> ⚠️ **后端选择会影响体验**：onnx（默认，仅 onnxruntime）RTF ≈ 6.1，
> 一句 6 秒的话要 37 秒才出声 —— 那时气泡早消失了。
> 你机器有 CUDA，建议用 `--backend torch`（RTF ≈ 0.45，约 3 秒/句）。
> 若只能用 onnx，把「每次朗读字数上限」调到 20~30 字会更跟得上。
